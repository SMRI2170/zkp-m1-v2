# 想定質問と回答：研究の解像度を上げる

発表では、実装済み・設計済み・未検証を混同しない。

## 1. RSSIで位置詐称を検知できるのか

**答え:** RSSIだけで絶対位置を確定しない。放送位置と端末位置から計算した幾何距離と、RSSIから得るおおまかな距離帯が著しく矛盾するかを判定する。

```text
主張しない: 「この座標に必ずいる」
主張する: 「放送座標は受信強度と著しく矛盾する」
```

- 実装済み: 相対許容帯を使う整合判定をZK回路内で計算する。
- 未検証: 建物内・遮蔽・端末機種差での誤検知率。
- 次の実験: 距離、遮蔽物、端末種別を変えたデータでROCとK-of-N閾値を評価する。

## 2. Remote ID自体が偽ならどうするのか

**答え:** 署名付きRemote IDなら、leaf回路でオペレータ鍵の署名を検証し、`drone_auth_ok = 1`だけを集約する。署名は「鍵保有者が送った」ことを示すが、鍵保有者自身の虚偽位置までは防がない。その物理的不整合を複数端末のRSSI観測で検知する。

明示する前提は、公開鍵配布・失効、未署名機の扱い、鍵漏えい時の運用である。

## 3. Sybil攻撃を本当に防げるのか

```text
同じ登録端末の複数回参加       → nullifierで防ぐ
攻撃者が多数の登録端末を持つこと → 登録制度が防ぐ
```

**答え:** nullifierは `device key + session` から導かれる。同じ端末を同じsessionで再利用すると、使用済みslotを未使用として証明できないため失敗する。ただし、攻撃者が多数の正規登録端末を持つことは暗号回路だけでは防げない。本人性確認、端末上限、失効、stakeなど登録制度の設計が必要である。

## 4. 集約者は不正できないのか

**答え:** 集約者は結果を任意に決められない。回路は、固定VKでの子proof検証、session情報の一致、nullifier rootの連結、countの加算を強制する。不正なcountには対応するproofがないため最終proofを作れない。

ただし集約者は通信を止める、順番を遅らせる、送信元IPを観察することはできる。これは正しさではなく可用性・metadata privacyの問題であり、複数relay、遅延送信、batch化で対処する。

## 5. rootから端末や観測内容を逆算できないか

**答え:** Merkle rootからleafを逆算するにはhashのpreimage耐性を破る必要があるため、GPS、RSSI、端末鍵、nullifier値はrootから復元できない。

しかしrootを端末ごとに時刻付きで公開すれば、「この瞬間に1人が参加した」イベント列は分かる。外部の目撃情報やIPと結び付ける相関攻撃は残る。したがって端末ごとのrootは公開せず、K件または一定時間のbatch後に最終rootだけを公開する。

## 6. Novaを入れれば再帰集約は完成するのか

**答え:** 完成しない。Novaは `z(i+1) = F(z(i), w(i))` という逐次状態遷移に強く、nullifier rootとcountを1台ずつ更新する部分には合う。一方で、既存Circom/Groth16 leafを接続するBridge、二つの既存集合の非交差union、EVM用Decider、モバイル性能測定は別途必要である。

発表では、Novaを採用確定の解決策ではなく、有力な比較候補と表現する。

## 7. なぜEVMが必要か

**答え:** 行政・運航者・観測協力者など独立主体が、同じ判定規則と確定recordを監査する用途では意味がある。単一組織の内部監視だけなら、署名付きDBの方が安価で速い。EVM方式と中央DB方式の信頼仮定・費用を比較対象にする。

## 8. EVMまで本当に動く段階か

| 実装済み | 未完了 |
| --- | --- |
| 9入力v1 ABIと値域検査 | 実PCD rootからの最終BN254 proof |
| V1 registryのpolicy/root/version/session検査 | 生成済みSolidity verifier artifact |
| Solidity Hardhat 36件のテスト | ceremonyとartifact公開 |

**答え:** 契約の状態機械は実装済みだが、実proofによる完全E2Eは未完了である。

## 9. trusted setupをどう信頼するのか

**答え:** Groth16を最終境界に使うなら、複数者ceremony、少なくとも一人が秘密乱数を破棄したという仮定、source/R1CS/VK/verifier bytecodeのhash公開が必要である。manifestスクリプトは実装済みだが、本番ceremonyは未実施である。透明setupのNova/Spartan系Deciderも比較するが、EVM費用・成熟度の実証が必要となる。

## 10. 研究の新規性は何か

**答え:** 単一のZK回路ではなく、以下を1本の検証経路に結合する点にある。

```text
署名付きRemote IDの真正性
 + RSSIと位置の物理整合
 + 複数登録端末のK-of-N
 + nullifierによる一回性
 + 再帰proofによる集約
 + EVM上の最終record
```

ただし新規性は既存研究比較があって初めて主張できる。Remote ID検証、RSSI位置検証、ZK nullifier、recursive aggregationを比較表にし、未解決の組合せを明示する必要がある。

## 発表で守るべき表現

| 避ける表現 | 正確な表現 |
| --- | --- |
| 完全に匿名 | 生データは秘匿するが、metadata相関は別対策が必要 |
| 位置詐称を確実に検知 | 物理的な著しい不整合を検出する |
| Sybil攻撃を防ぐ | 同一登録端末の重複参加を防ぐ。多端末保有は登録制度の課題 |
| EVMまで完成 | ABI・registryは実装済み。実final proof E2Eは未完了 |
| Novaで解決 | Novaは順序付きstate遷移の有力候補。BridgeとDeciderが必要 |

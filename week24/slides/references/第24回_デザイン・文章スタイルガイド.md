# 第24回修正版：AI向けデザイン・文章スタイルガイド

## 1. このガイドの使い方

参照元は[ユーザー修正版の第24回スライド](第24回進捗_HyperNovaとNova_環境構築_実装.pptx)。23枚を描画して構成を確認し、PPTX内の文字属性・座標・段落設定も抽出した。研究内容の正誤の評価・再利用はこのガイドの対象外。

今後のAIは、**ユーザーの最新指示、修正版スライド、このガイド**の順で優先する。主に通常本文ページのスタイルを基準にし、表紙・目次・比較表・グラフはそれぞれの構成を使い分ける。

### 今回のユーザー指定を優先する点

- **新規作成・改訂版のスライド番号にはPowerPointの自動フィールドを使う。** 最新指示により、以前の番号なしの指定を更新。マスター／レイアウトにも番号プレースホルダーを設ける。
- **丸・四角ともPowerPoint標準の箇条書きを使う。** 「・」「■」を本文先頭へ直接入力しない。
- **発表者ノートを作成しない。** 必要な説明は本文、出典は短い可視表記または別の出典資料へ。
- 毎ページの下部に同じ結論ボックスを置かない。必要な結論は本文へ組み込む。
- zk-SNARK概要を再説明しないという指示は今回の発表に適用する。将来の全発表から永久に除外する規則ではない。

## 2. 全体の見た目

| 項目 | 原本で確認した設定・使い方 | AIが再現する内容 |
|---|---|---|
| ページ | 4:3、10 × 7.5インチ、25.4 × 19.05cm | 指定がなければ4:3。勝手に16:9へ変更しない |
| 背景 | 白 | 白地を基本に余白を確保 |
| タイトル | 上端の薄灰色帯に、左寄せの太い黒文字 | 名詞句で主題を短く提示 |
| 導入の一文 | タイトル下の青文字と細い青の縦線 | そのページで説明する範囲・着眼点を1行程度で提示 |
| 本文 | 黒文字、青い「■」の小見出し | 小見出し単位で説明をまとめる |
| 強調 | 赤い語句・記号・問い、太字 | 読ませたい箇所に限定。段落全体を赤くしない |
| 表 | 濃い青の見出し行、白文字、薄青と白の本文行 | 条件・方式・結果の対応を縦横で比較 |

## 3. 文字と色

### フォントとサイズ

原本の主要フォントは `Hiragino Kaku Gothic ProN W6` と `Hiragino Kaku Gothic ProN W3`。一部に游ゴシックもあるが、通常ページの基準はヒラギノ。

| 用途 | 再現の基準 |
|---|---|
| 通常タイトル | W6、26pt、太字、黒 |
| 青い導入文 | W6、18pt、太字 |
| 青い小見出し | W6、17〜20ptを目安 |
| 本文 | W3、16〜18ptを中心に使用 |
| 表の本文 | 15〜17ptを中心に、元レイアウトに合わせる |
| 独立した中心式 | 周囲の本文より大きく、概ね24〜28pt相当を目安 |
| 表紙 | 中央寄せ。主題を大きく、所属・氏名・日付を控えめに配置 |

サイズには原本内のばらつきがある。上記を全要素へ機械的に適用せず、同種の参考ページへ合わせる。詰まったら文字を縮める前に文章を削るかページを分ける。フォント未導入の場合は、代替を黙って使わず日本語の字形と改行を確認する。

### 色の役割

| 色 | HEX | 用途 |
|---|---|---|
| 本文の黒 | `#282629` | 通常本文、タイトル |
| 基本の青 | `#2F64A1` | 導入文、小見出し、本文内の整理 |
| 表見出しの濃い青 | `#2B5581` | 表ヘッダー、白い見出し文字との組合せ |
| 薄灰色 | `#F3F4F6` | タイトル帯 |
| 薄青 | `#EDF3F7` | 表の交互行 |
| 赤 | `#FF0000`、一部 `#E02B2B` | 注目する変数、対象行、制約・未確認箇所、重要な問い |

**青は構造、赤は局所的な注目、黒は説明**という役割を守る。赤は「危険・不正」の専用色ではなく、対象行や変数にも使われている。赤だけで評価状態を表さず、「未確認」「今回の対象」などの語も併記する。目次では現在扱う章を赤くする使い方がある。

## 4. 体言止めと文章のまとめ方

### 基本方針

- タイトルと小見出しは名詞句を基本にする。「測定条件」「処理時間の比較」「今回の確認範囲」など。
- 作業・結果の要約は「調査」「確認」「比較」「実行」「整理」「未確認」「未測定」などで短く締める。
- 本文は1項目1論点。前提・結果・限界を同じ長文へ詰め込まない。
- すべての行を無理に体言止めへ変えない。条件や因果関係が曖昧になる場合は、短い説明文を残す。
- 「しました」「していきたいと思います」「ということが分かりました」など、発表者の動作を述べる言い回しを減らす。
- 「未確認」を「不可能」、「未測定」を「性能が低い」へ置き換えない。短文化しても保証・事実の強さを変えない。
- 小見出し・箇条書きは通常、末尾の「。」を付けない。長い説明文では読解に必要な句読点を使う。

### 変換例（書き方の例であり、新しい研究結論ではない）

| 長い書き方 | この参考に合わせる書き方 |
|---|---|
| A方式とB方式の処理時間を比較しました | A方式・B方式の処理時間の比較 |
| 同じ回路を使って測定を実施しました | 同一回路による測定 |
| 実装されている範囲を調べました | 実装済み範囲の調査 |
| この条件で動くかはまだ確認できていません | この条件での動作は未確認 |
| 今後は反復実験を行っていきたいと思います | 独立した反復実験による再評価 |
| この仕組みについて説明します | 仕組みの名称を見出しにし、本文から説明を開始 |

名詞だけの羅列も避ける。「方位・位置・識別」だけでは関係が分からないため、「方位から絞れる位置の範囲」のように関係を残す。

## 5. 箇条書きとインデント

原本の通常ページは、青い小見出し、主項目、字下げした補足の順に読む。

```text
■ 測定条件                     ← 青・太字。話題のまとまり
  ・同一回路・同一入力列での比較  ← 主項目
      ・実行条件と集計範囲の固定  ← 上の項目を補う条件

■ 比較上の限界
  ・異なる測定範囲の混在
      ・単純な優劣の判断は保留
```

これは意味階層の例。実ファイルでは空白や全角スペースで字下げを作らず、**ネイティブの段落・箇条書き設定**を使う。

### 原本から抽出した通常本文の代表値

| 段階 | `marL` | `indent` | pt換算 |
|---|---:|---:|---|
| 主項目 | 285750 EMU | −285750 EMU | 左余白22.5pt、ぶら下げ−22.5pt |
| 補足項目 | 742950 EMU | −285750 EMU | 左余白58.5pt、ぶら下げ−22.5pt |

補足項目は主項目より36pt右へ。座標はテキスト枠の内側基準で、スライド上の絶対位置ではない。枠の左端・内側余白も加味する。使用するAPIのインデント単位へ変換し、EMUの数値を別単位のAPIへそのまま渡さない。

通常本文では段落前3pt、後1pt、小見出しでは前8pt、後2.5ptの代表例を確認した。ただし個別に変更されているページもあるため、視覚上のまとまりを優先する。

- 主項目と補足の論理的な関係を守る。2行目だから自動で下げる、という扱いはしない。
- 折り返した行は本文開始位置へ揃え、箇条書き記号の下へ戻さない。
- 原則は2階層。最後の問い・追加確認事項に限り、原本には矢印記号の第3階層もある。
- 同格の項目は同じ字下げ・文字サイズ・行間へ揃える。

## 6. レイアウトの代表値

通常ページのPPTX内座標をcmへ換算したもの。例外ページがあるため、位置の「基準」として使う。

| 要素 | 左x | 上y | 幅 | 高さ |
|---|---:|---:|---:|---:|
| 通常タイトル | 1.10cm | 0.25cm | 23.20cm | 約1.10cm |
| 青い導入文 | 1.60cm | 2.25cm | 22.70cm | 約0.76cm |
| 通常本文枠の例 | 約1.11cm | 約3.44cm | 約23.02cm | 約12.96cm |

文字サイズのpt、図形座標のcm、内部保存のEMUを混同しない。元の比率を維持し、タイトル帯・導入文・本文の開始位置を揃える。下端に毎回別の結論帯を増設しない。

## 7. 図・表・数式の配置パターン

### A. 説明主体（原本5・22・23枚目）

- 上部に主題、必要なら青い導入文
- 青い小見出しごとに1〜3個程度の主項目
- 補足・条件は1段深いインデント
- 最後の重要な問いは本文中で短く強調
- 「まとめ」と「今後」は別ページ

### B. 数式・用語の説明（原本6〜11枚目）

- 小見出しの下に中心式
- 式の近くに「記号：意味」を1行ずつ配置
- 注目する秘密値・変換項などを赤で強調
- 下部に「式の読み方」「その式を使う意味」「確認する条件」などを配置
- 必要なら2ページに分け、タイトル・式の位置を固定したまま説明だけ追加
- 全記号を先に一覧表へ詰めず、使う式と同じページで説明

数式の貼付画像は原本にもあるが、新規作成では可能なら編集可能な数式を使う。参照元の画像を小さく引き伸ばして再利用しない。

### C. 表と補足（原本2・13・14・20・21枚目）

- 表を本文上部〜中央に大きく配置
- 濃い青の見出し、白文字、本文は白／薄青の交互行
- 行ごとに同じ種類の情報を並べ、単位を見出しかセルへ明示
- 表の下に「数値の読み方」「集計方法」「未測定の項目」などの短い補足
- 注目する行だけ赤。表全体を強調色にしない

### D. グラフと読み取り（原本15〜17枚目）

- グラフを中央で最も大きくする
- 系列は濃淡の青を基本とし、系列名・単位・軸・数値を確認
- 下部には読み取りと条件を少数の箇条書きで配置
- グラフの数値を本文へ全件重複させない
- 目盛・文字が小さくなればグラフ数を減らすかページを分ける

### E. 目次と章の位置（原本3・4・12・18枚目）

- 同じ目次を章の区切りで再掲
- 今扱う章のみ赤くして位置を示す
- すべてのページへ進行表示を常設しない
- 今回の発表が短ければ、再掲回数も減らす

## 8. そのまま再現しないもの

原本の内容、誤字、研究上の断定、実験値、個人名・日付を新しい発表へ自動転用しない。対象内容の根拠は別途確認する。個別に追加された画像や注釈の位置を全ページ共通の規則にしない。重なりや文字切れを参考スタイルとして再現しない。

スライド番号・ノートの有無は、原本の見た目よりユーザーの最新指示を優先する。

## 10. 出力前の確認

- 主題が名詞句として読み取れるか
- 「しました」「説明します」などの発表者の語りが残っていないか
- 同格項目のインデントと、補足の階層が揃っているか
- 色の役割が一貫し、赤が多すぎないか
- 記号の意味と図・表の読み方が、そのページで分かるか
- 数値・未確認・限界の意味を、体言止めへの変換で変えていないか
- スライド番号が自動フィールドか。丸・四角が段落の箇条書き設定か。ノート・定型の下部ボックスがないか
- 実際に描画し、改行・文字切れ・重なり・読める大きさを確認したか

## 今回作ったもの

観測者の位置・RSSI・観測時刻をprivate witnessとし、公開された申告位置・判定方針に対して、**整合／警報／品質による保留**を正しく計算したことを制約するgnark回路。BN254のR1CSにコンパイルして合成入力の充足性を検査する。既存aggregatorとは別Go moduleで依存版だけ揃えた。

**「実際の位置が正しい」「本当に電波を受けた」「自由な送信電力でも位置偽装を検知できる」という証明ではない。**

## 再実行

リポジトリルートから：

```sh
cd week_tmp/circuit-design
DRAFT_SUMMARY_PATH=results/constraint-summary.json go test -count=1 -v ./... > results/circuit-tests.log 2>&1
```

`results/constraint-summary.json`へ制約数・テスト数・未実施項目を出力する。通常コマンドはsetup/proofを生成しない。別の明示的opt-in単体試験ではメモリ内だけでsetup/proofを生成・検証する。EVM成果物は生成しない。合成fixtureはテストコードだけに置き、実captureや座標は使わない。

## 採用判断

今回の距離帯別RSSI範囲は、計算制約を検査するための**任意の合成値**。GhostBuster原著アルゴリズムの再実装でも、実測に基づく検出器の採用でもない。実測解析が別の判定式を支持すれば、Week32前に差し替える。既存の「RSSI→推定距離」を信用する回路をそのまま利用しなかった理由もDESIGN.mdに記載した。

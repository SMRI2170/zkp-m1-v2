# 今回の実測データで位置偽装を検知できるか・何を秘密にするか

更新：位置・高度・時間の誤差を扱う別statement `UncertaintyCircuit`と、実データの監査/感度分析を[追加報告](uncertainty/README.md)に実装・記録した。以下の「現試作3D」は当初の`Circuit`を指す。追加回路は2D/3Dを分離するが、実データの高度精度と共通高度基準は依然未確認。

後続：[署名付き回路と合成単体proof](SIGNED_DESIGN.md)を実装・実行。以下の未接続項目は当初試作の履歴であり、実測入力と登録鍵・原本への接続は引き続き未完了。

確認日：2026-11-24。対象はWeek29の実機Remote ID観測と既存解析。新規実験・モデル再学習は今回行っていない。

## 1. 現時点の答え

**実際の位置偽装を検知できたという根拠は、今回のデータからは得られていない。** 一方、実測RSSIを残した合成位置変更への反応と、電力補償に対する限界は確認できた。

品質条件を通過したPixelの105行を時間順52/26/27行に分けた既存評価では、次の結果だった。ここでのPixelは記録上の端末名であり、Pixel 8とは別。対象実機のPixel 8記録はなかった。

| 評価27行への処理 | 警報 | 読み取れること |
|---|---:|---|
| 未改変 | 13/27（48.15%） | 正常相当の記録にも高い警報。物理的な正常真値は未確認 |
| 申告を受信局から50m遠方へ合成変更 | 27/27（100%） | 同じ評価記録でモデル不整合が増加。ただし13件は元から警報、変更後は全件が学習距離域外 |
| 上記変更＋同モデルの上限なし電力補償をRSSIへ合成加算 | 13/27（48.15%） | 残差を元に戻す補償では、元の記録との警報差も消える |

この100%を実機偽装の検出率としない。RSSIは実測だが攻撃は後処理による合成、独立真位置・実際の攻撃ラベル・独立飛行runはない。校正26行の残差95分位は実誤警報率5%の保証ではない。

## 2. 今回の入力だけでは不足すること

- 元のRID位置は申告値であり独立真値ではない。3D再生も申告軌跡の再生である。
- 同一物理送信と確定した多局対応は0件。内容一致候補から未知電力が消えたとは主張できない。
- 既存B解析の設置座標は未確定だった。利用者が持つ位置台帳をrun・有効期間へ対応させる作業は#89の残件。後で台帳を得ても、同一送信や独立真値が自動的に得られるわけではない。
- スマホ/機体の高度基準が未整合で、現在の実測解析は水平距離のみ。高度偽装の検出や3D距離の性能は未評価。
- 申告距離に対するOS精度の比率で選別すると、申告を遠くするだけで通過しやすくなる。現探索条件をそのまま回路の信頼性ゲートへ採用しない。

研究上言えることは「今回の単局水平モデルの採用は支持しない」「電力の自由度・モデルの知識・追加観測条件を分ける必要がある」である。未知電力下の全ての方式が不可能だと一般化する結論ではない。

## 3. 回路で証明するstatement

候補は次とする。

> 承認された観測者の署名済み記録に結合した非公開の位置・RSSI・時刻を使い、固定された判定方針に従うと、この整合／警報／保留という結果になる。

「記録に署名した」「判定計算が正しい」「位置申告が真実」は別。署名しても受信機が嘘をつく可能性や、入力自体の誤りは消えない。

現在の`circuit.go`は距離二乗・距離帯別RSSI区間・品質・commitmentの**計算核のみ**。観測者署名、資格、replay防止、承認profileの照合、元RIDの正規化は未接続。自分で都合のよいwitnessとcommitmentを作れば制約を満たし得るため、現試作単体を観測の証拠として受け入れない。

## 4. 秘密にするもの・公開するもの

| 項目 | 推奨する扱い | 理由と注意 |
|---|---|---|
| 観測者の正確な位置・移動軌跡 | private witness | 観測者の所在・行動を保護。位置の正しさそのものは別途根拠が必要 |
| 観測RSSI・受信原本 | private witness/私的保存 | 個々の受信状況を保護。署名済み記録と計算入力の結合が必要 |
| 正確な受信時刻・GPS時刻/精度 | private witness | 移動履歴の推測を抑える。公開run/時間窓との対応は検査する |
| 機体のRID申告位置 | まず公開入力 | 「どの申告を検査したか」を固定する。受信機が私的な別位置へすり替えられないようにする |
| 機体の生RID | 原則公開しない | run限定のclaim token/commitmentを使う。元RIDとの正規対応・salt管理は別途設計する |
| 方針・モデル版・閾値・座標系ID | 公開・verifierで承認確認 | proverが都合のよい閾値や座標系へ変更するのを防ぐ |
| 整合/警報/保留と対象run | 公開 | 判定を利用するための最小情報。整合を真位置認定と表示しない |
| 観測者の資格 | 検証可能な資格情報 | 初版は登録公開鍵で簡素化可能だが継続追跡される。匿名化するなら会員証明とrun限定nullifierを別設計 |
| 観測者秘密鍵 | 端末内の署名処理だけ | 他者のproverやサーバーへ渡さない。回路が必要とするのは署名の検証で、秘密鍵そのものではない |
| commitment用nonce | private witness | 十分なランダム性を外部で確保。短いnonceやテスト定数を本番流用しない |

「申告位置も秘密」にしたい場合は別statementとする。公開された元RID packet/claim commitmentへ署名とともに結合し、privateな申告位置がその記録と一致することも証明しなければならない。今回の試作では申告位置とClaimTimeは公開。申告時刻も隠す設計へ変える場合は回路と公開schemaの変更が必要で、すでに実装したとはしない。

commitmentを公開しても観測の真実性は得られず、固定鍵・token・判定結果の反復公開はリンクや位置推測を招き得る。公開項目を全部ゼロ知識で隠せば解決するものではなく、照会単位・頻度・session期限も決める。

## 5. 今回のデータへ接続するなら2Dから

1. #89で自己位置、時刻、観測原本の対応を固定し、申告値に依存しない品質条件を用意する。欠測はゼロ補完せず評価不能にする。
2. 同じ局所座標系へ正規化した申告点qと観測者点oを使い、まず水平二乗距離`(qx−ox)^2+(qy−oy)^2`を対象にする。
3. モデルと閾値は校正側だけで固定し、独立runの正常基準と合成攻撃を評価する。現モデルは不採用のまま保持し、回路化の都合で採用しない。
4. 採用モデルが決まれば整数/固定小数点仕様と近似誤差を定義する。境界では誤差を含めた保留帯を設計し、元の浮動小数点判定との一致/不一致を検査する。
5. canonicalな署名済み観測・承認policy・session・claim・観測者資格を回路またはverifierへ結合し、データ差し替え/再利用の否定テストを行う。
6. 実際のproof生成・検証を行う。制約テスト成功とZK証明成功を区別する。

**現試作は3Dの合成テスト用で、現在の実測27行へそのまま適用する設計ではない。** 未確認高度を0として渡して3D距離を作らない。2D版を実装する際は別statement/domainとして固定し、2Dと3Dの判定を取り違えない。距離帯RSSI区間も現在は任意の合成値で、今回の固定logモデルとは異なる。

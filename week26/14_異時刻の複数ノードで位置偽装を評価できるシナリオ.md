# 異時刻の複数ノードで位置偽装を評価できるシナリオ

2026-11-01。ユーザーの目的を「ノード数・配置・観測時刻が異なり、ドローンは送信電力を変更できる状況で、RIDの位置申告の偽装を判定する」として整理。既存コードの適用範囲と一次資料を照合した調査メモ。新しい飛行・検知性能の実験結果ではない。

## 1. 先に決めるべき時間の意味

**非同期のアップロード**と**異なる送信の受信**を分ける。

- AとBが同一の物理送信を受信し、Aはすぐ、Bは5分後に提出：後から同じ送信イベントのRSSIを比較できる。提出の遅れだけでは共通送信電力の性質は失われない。ただしリアルタイムには間に合わない。
- Aは10:00の送信、Bは10:01の別の送信を受信：電力・機体位置・姿勢・経路が変わり得る。差分を取るだけでは電力が消えない。
- Aは今日、Bは翌日、同じRID文字列を受信：同一物理機体や同一電力の観測と自動的に見なさない。RID文字列によるグループ化は機体認証ではない。

ここでいう同一イベントは、同じRID文字列・同じ位置ペイロードというだけでは足りない。繰り返された広告、再送、異なるチャネルやPHYの別送信を誤ってまとめる可能性がある。実装では受信時刻の不確かさ、PHY/チャネル等の取得可能情報とペイロードを使った対応付けが必要。その対応付け自体の誤りも評価対象で、機体側の申告時刻だけを正解にしない。

## 2. 送信電力を変えられると何が変わるか

校正済みの受信機で、単純化した観測式を考える。

```text
r_i,e = a_e − 10 n log10(distance(p_e, observer_i)) + error_i,e
```

`e`は物理送信イベント、`a_e`は未知の共通実効基準電力、`p_e`は未知の真位置。`q_e`は不信頼なRID申告位置。`a_e`は送信機のEIRPを独立に測った値ではない。

**1イベントを1ノードしか受けない場合**、候補位置を変えても、その分だけ`a_e`を変えれば同じRSSIを作れる。別イベントの電力も自由なら、ノードを増やしただけではこの自由度が消えない。距離推定値や異常スコアを計算できることと、原因が位置偽装だと識別できることは別。

**同じイベントを複数ノードが受ける場合**は、RSSI差から共通の`a_e`を除ける。その送信以前・以後に電力が変わっても、そのイベント内の共通成分は除去可能。ただし受信機差、経路差、方向依存のアンテナ利得は別に残る。単一送信源、同じ送信イベントの対応付け、適用可能な伝搬モデルを仮定する。

イベントごとに受信ノードが`m_e`個なら、共通電力を除いた後に残る差分の数は最大`m_e−1`。これは測定式の数であって、独立した3D位置拘束の保証ではない。`m_e=1`では自由電力を除去した位置検査の情報が残らず、`m_e>=2`でも一意な位置復元や全偽装の拒否を保証しない。

この区別はDRSSの一次資料の式(1)・(2)とも対応する。同論文は受信電力を取る構成と共通電力・電力差の扱いを明記し、電力差に統計的な仮定を置いている。任意時刻の任意な攻撃電力を、無条件に除去する定理ではない。[Hu and Leus, IEEE TSP 2017、公開本文](https://arxiv.org/pdf/1807.03530)

## 3. 現在のコードで扱えるシナリオの対応表

| シナリオ | 目的に対して言えること | 今の実装・データでの状態 |
|---|---|---|
| S0：A・B・Cが別時刻の別フレームを1台ずつ受信。各送信で電力自由 | 一般的な位置識別不能性の反例。モデルに対する異常度は出せても、位置偽装の確定にはならない | 最小反例・非同期の単一リンク感度評価は実装済み。共通機体がA→B→Cを通過するネットワーク追跡は未実装 |
| S1：同じフレームを複数ノードが受信。提出時刻だけ異なる | 共通電力を除いた申告位置との整合性検査。一部の位置偽装を棄却できる条件を評価可能 | 同一イベント・既知配置の合成スコアは実装済み。提出遅延、対応付け、時計誤差、欠測を含むフローは未実装 |
| S2：観測時刻はまちまちだが、一部のフレームだけ複数ノードで重複受信 | 重複イベントでは電力の共通成分を除き、単独受信部分では保留。判定できる時間の割合を評価 | S1とS0の部品はある。単一の連続軌跡・受信範囲・イベント対応を結んだ統合シミュレーターは追加が必要 |
| S3：別フレームを近い時刻に受信し、期間内の電力変化と移動に根拠ある上限を置く | 上限の下での条件付き判定。どの変化量で破綻するかを評価 | 電力相関モデルの感度評価はある。任意時刻の複数ノードを束ねる実装や、変化速度の上限に基づく検査はない |
| S4：完全に非重複の観測に、独立した方向・距離・位置の証拠を追加 | RSSIだけの曖昧さを減らす可能性。独立観測の精度・時刻・機体対応が別途必要 | カメラ・AoA・TDoAとの統合評価は未実装。取得済みLoRaだけでは再現できない |

S3の「近い」は秒数だけで決めない。例えば0.1秒でも、その間に別フレームの電力を変更可能なら、共通電力の差分としては扱えない。移動速度と電力の変化速度の両方に上限を置くなら、その根拠と違反時の動作を明記する。RIDが自己申告する電力・速度は、独立な上限の証拠にならない。

## 4. ユーザーの目的に最も近い評価用シナリオ

**施設または通過経路に置いた複数受信ノードが、機体の通過中にRIDを観測。一部だけ受信範囲が重なり、ログ提出は非同期。** ノード数や配置は感度評価の変数とし、固定台数での保証は主張しない。

次は検討用の例で、実測から決めた送信周期・台数ではない。

| 物理送信イベント | 受信できたノード | 検査の扱い |
|---|---|---|
| e0 | A・B | 同一送信のRSSIを比較。2ノードだけで全方向の偽装を検知できるとはしない |
| e1 | Bのみ | 自由電力に対する位置判定は保留 |
| e2 | B・C・D | そのイベントで共通電力を除いた整合性検査 |
| e3 | Dのみ | 保留。e2で整合したことを現在位置の保証に延長しない |

各イベントの電力は変えてよい。**重複受信したイベントの情報量と、単独受信しかない時間帯の扱いを分ける**ことが要点。保留部分を前後の軌跡で埋めるには、追加の移動モデルとその適用条件が必要。前後のRID申告だけで真の連続軌跡が分かったとはしない。

まず必要なのは、合成真値として1本の機体軌跡と各イベントの電力を生成し、同じイベントから各ノードのRSSIを生成する構成。各ノードへの到達、受信感度、スキャン欠測、時計誤差、後日の提出を別の段階で表す。これを、既存の単一リンク再割当て実験と区別する。

評価出力は次の4種類が適切。

1. 正常時の誤警報率。
2. 判定できたイベントでの位置改変検知率と、全イベントに対する検知割合。
3. 判定保留率、同一送信を複数受信できた割合、誤ったイベント対応付け率。
4. 受信から判定までの時間。アップロードを待つ時間を含める。

送信電力の変更だけで警報が増えるか、位置と電力を合わせて変更するとどうなるかも分ける。単独受信部分を全て保留して高い条件付き検知率だけを示さない。

## 5. 複数受信機でも残る幾何学的な反例

雑音なし・校正済み・全ノード共通の伝搬指数という理想条件でも、全ノードへの距離が同じ比率で変わる2位置があると、共通電力で補償できる。

例：地上の半径100mの円周上に4受信機を置き、真位置が円の中心上空20m、別候補位置が同じ中心上空80m。

```text
真位置から全受信機への距離       = 101.9804m
候補位置から全受信機への距離     = 128.0625m
伝搬指数2.2で必要な共通電力の差   = +2.1759dB
```

候補位置側の基準電力をこの分だけ増やすと、全4ノードで同じRSSIを作れる。Python標準ライブラリで式を代入し、差0dBを確認しただけの数理例で、実機攻撃ではない。したがって「複数ノードだから必ず解決」「4台なら必ず3D位置が分かる」とは結論しない。配置・高さ・偽装方向も評価する。

## 6. 既存コードの監査で分かった制限

- [`simulate3d_independent.py`の`generate()`](../experiments/week26-rssi-privacy/simulate3d_independent.py)：各flightに受信機1台を割り当て、その受信機を基準に局所座標の軌跡を作る。**単一機体を複数ノードが順に観測する共通座標のシミュレーターではない。**
- [`sensitivity_suite.py`の`remap_async()`と`async_study()`](../experiments/week26-rssi-privacy/sensitivity_suite.py)：観測数を固定したまま受信機ラベルと校正差を変える比較。ノード数増加で空間的な重複受信や同一軌跡への制約が増える評価ではない。
- 同ファイルの`synchronous_study()`：共通の1イベントの位置から複数ノードへの距離を計算し、共通電力を消去する。これはS1の部品。スナップショットで、連続移動・受信空白・提出遅延・対応付け誤りは入っていない。既知伝搬指数、簡略雑音等の前提がある。
- `time_study()`：独立な真距離付き過去観測と、仮定した電力相関から条件付き予測。RID座標を独立な真距離として学習したものではなく、S0の任意攻撃への解決ではない。
- [`recheck_lora.py`](../experiments/week26-rssi-privacy/recheck_lora.py)：実飛行中の1リンクの時刻対応・距離近似・窓幅等。ノード間同時受信の実測を再現するものではない。

既往の[結果10](10_偽装距離_端末数_時間差_RID別学習の追加評価.md)、[結果12](12_実測揺らぎと学習汚染_モデル失効の追加評価.md)、[結果13](13_公開UAV実測データの入手とLoRa再解析.md)の数値は、それぞれの前提の結果として保持する。今回のコード監査で、それらをS2の統合ネットワーク実験の結果に読み替えない。

## 7. 一次資料との対応と信頼境界

- [Hu and Leus, Robust Differential Received Signal Strength-Based Localization](https://arxiv.org/pdf/1807.03530)：式(1)・(2)と導入を確認。共通電力の除去と受信ごとの電力差を分け、後者に統計モデルを置く。任意の異時刻攻撃を無条件に処理した証拠ではない。
- [Li et al., CTUP、公開本文v1](https://arxiv.org/html/2406.14664v1)：IIのモデル、未知電力・伝搬指数・アンカー位置誤差の扱いを確認。複数リンクを使うパラメータ推定の研究で、1観測につき独立な任意電力を持つ移動RID攻撃の解決として引用しない。
- [GhostBuster、公開本文](https://pure.tue.nl/ws/files/343585890/GhostBuster_Detecting_Misbehaving_Remote_ID-Enabled_Drones.pdf)：VI-A/C、VI-Dを確認。複数観測者の評価は1センサの実測から導いたチャネルモデルによる拡張を含む。位置と送信電力の議論はあるが、幾何学的な例外や本研究の完全非重複条件まで無条件に解決したと解釈しない。

各構成では、観測ノードの位置・時計誤差・RSSIの報告が適切という条件を別に置く。ZKPや署名は、固定した入力・モデル・判定計算の検証に使い得るが、電波やセンサが正直であることを自動証明しない。V2は申告RIDの観測者署名付き主張を扱う研究PoCであり、DRIP信頼連鎖、機体や観測ハードウェアの認証を実現したものではない。

**判断：完全に重なりのない別送信の観測だけを維持するなら、RSSI単独での一般的な位置偽装判定は成立しない。目的に近いRSSIの研究シナリオはS2だが、重複のない部分を保留にする条件を受け入れ、統合実装と対応する実測データが必要。**

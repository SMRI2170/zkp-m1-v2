# Week29：修正・研究報告の公開範囲と検証（2026-11-19）

## 公開する変更

- Pi：役割・起動セッション別の保存分離、保存予算とSD/RAM余力による理由付き停止、health、保全／照合と非有効化stage。既存captureを自動削除しない。
- Android：v0.14のSQLite分割保存・既存DB保持・失敗診断。公開mainに未反映だったv0.12/0.13の権限案内・最短スキャン方針と関連共有コードも含める。
- 解析：Week29の監査・同一送信候補・申告距離／RSSI・合成攻撃・採用manifest・監視／描画コード、匿名集計、報告。
- CI：Week29解析と公開境界検査。OpenDroneID参照C実装は固定commit／SHA-256を検証して構築し、参照デコード3テストを必須実行する。本番パーサの受理条件は変えない。

最新origin/mainを基点に専用ブランチへ選択転送した。元の作業ブランチの未整理差分、Week24〜27の別成果、既存PRの未マージ差分をまとめて取り込んでいない。元作業ディレクトリの変更・生データは保持している。

## 公開しないもの

生capture JSONL、SQLite、実座標、真値台帳、実機ID/BSSID、鍵、認証情報、私的接続設定、行単位の採用mask、3D軌跡HTMLは含めない。従来ローカル出力にあった`source_rssi.csv`・`candidate_intervals.csv`・`update-intervals.csv`も公開対象外とした。

以後の解析でもこれら3種類の行単位CSVは`--private-output`へ書き出す。Bの描画には公開集計用`--input`と非公開行データ用`--private-input`を別々に指定する。元のローカルCSVは削除していない。重複するSVGはローカルに保持し、公開図はPNGへ整理した。CSVは改行をLFへ統一し、解析レコードが変わらないことを照合した。

固定した参照デコーダの上流ソースはCIキャッシュ領域へ取得し、バイナリや外部Cソース自体をGitへ追加しない。APKはCIのdebug artifactであり、リリース署名鍵や実機データを含めない。

## 再現とCI

```sh
python3 week29/scripts/build_reference_decoder.py
WEEK29_REQUIRE_REFERENCE=1 python3 -m unittest discover -s week29/tests -v
python3 -m unittest discover -s experiments/field-kit -p 'test_*.py' -v
python3 -m unittest discover -s experiments/week28-beacon-observers -p 'test_*.py' -v
python3 -m unittest discover -s experiments/kmp-rid-observer/tests -v
python3 -m unittest discover -s uav -p 'test_*.py'
python3 week29/scripts/check_publication.py
```

Goは`aggregator`で`go test ./...`、contractsは`contracts`で`npm ci`後に`npm test`。Androidは`.github/workflows/kmp-rid-observer.yml`のGradleタスクを使用する。私的な実測入力なしでも合成fixtureの単体テストと公開境界検査を実行できる。実測の再解析には所有者が保持する非公開入力が必要。

push後のCI結果・ログはGitHub Actionsを正本とし、実行SHAと結果をPR／関連Issueに記録する。ローカル検証JSONのCI状態はcommit時点の記録であり、CI成功を事前に主張しない。

## 研究上の限界

研究PoC。RIDは申告であり機体認証・DRIP・観測ハードの真正性・センサの正直さは保証しない。C/Dの4時間監視はWAITING・対象RID 0件であり、実ドローン受信・飛行時の保存性能の証明ではない。未知電力・非同期観測の識別不能条件、未改変13/27警報、同一物理送信未確認は公開によって解消しない。

# フレームワーク概要 — それぞれ「何者か」入門

作成日: 2026-07-17 / 目的: 各 ZKP フレームワークが**そもそも何なのか**を、
「何者か / 核の仕組み / 背景（誰が作ったか） / 代表的な使われ方」で平易にまとめる入門編。
比較・モバイル実行は [02_フレームワーク比較.md](02_フレームワーク比較.md) /
[03_モバイル実行の方法.md](03_モバイル実行の方法.md) を参照。※2026年前半時点。

---

## 読み方（前提の言葉）

- **回路(circuit)**: 「証明したい計算」を足し算・掛け算の制約の集まりに変換したもの。
- **証明系(proving system)**: 回路から証明を作り、検証する数学エンジン（Groth16 / PLONK / STARK …）。
- **トラステッドセットアップ**: 一部の証明系が事前に必要とする“鍵作りの儀式”。漏れると偽造の恐れ。
- フレームワーク＝おおむね「**回路を書く言語 ＋ 証明系エンジン**」の組み合わせ。

# A. 回路を書いて SNARK 証明を作る系（端末証明の定番）

## circom（＋ snarkjs）
- **何者か**: 回路を書くための専用言語(circom)と、証明を扱う JS ライブラリ(snarkjs)のセット。
- **核の仕組み**: circom で制約(R1CS)を記述 → snarkjs が Groth16/PLONK で証明生成・検証、Solidity
  検証器も出力。標準ライブラリ **circomlib** に Poseidon・EdDSA・比較などが揃う。
- **背景**: iden3（Polygon 系のゼロ知識チーム）が開発。ZK 界で最も普及した回路記述系の一つ。
- **代表例**: Tornado Cash、Semaphore、各種 zk 認証。**本案件の現行回路もこれ**。

## rapidsnark
- **何者か**: circom/snarkjs で作った回路の**高速な Groth16 証明生成器**（C++／アセンブリ）。
- **核の仕組み**: snarkjs と同じ証明を、ネイティブ実装で桁違いに速く生成。arm64 対応で端末でも動く。
- **背景**: 同じく iden3。snarkjs が遅い問題への“速いプローバ”。
- **代表例**: サーバ・**モバイルでのオンデバイス証明**（本案件のアプリが使用）。

## gnark
- **何者か**: Go 言語で書く**フルスタックの ZKP ライブラリ**。
- **核の仕組み**: Go で回路を記述、Groth16/PLONK を複数曲線で。**再帰検証**（証明の中で別の証明を検証）
  や Solidity 出力に対応。プローバが速い。
- **背景**: ConsenSys（Ethereum 系の大手）が開発。ロールアップ/インフラで広く採用。
- **代表例**: zkEVM・ロールアップのサーバ側。**本案件の集約(M2)がこれ**。

## Noir（＋ Barretenberg）
- **何者か**: Rust 風の**書きやすい高水準言語**。ZK を一般開発者に開くことが狙い。
- **核の仕組み**: Noir → 中間表現(ACIR) → バックエンドで証明。既定バックエンド **Barretenberg** が
  PLONK系(UltraHonk)で証明。**トラステッドセットアップは1回きり（回路別不要）**。Poseidon/EdDSA も揃う。
- **背景**: Aztec（プライバシーL2）が開発。近年モバイル/ブラウザ証明で採用増。
- **代表例**: Aztec、zk-email、パスポート系アプリ、クライアント証明。

## halo2
- **何者か**: **表現力の高い**回路が書ける Rust の証明系（PLONK系）。
- **核の仕組み**: 「chip/gadget」を組んで回路化。custom gate・lookup など高度な最適化が可能。
  KZG 版は準備1回、IPA 版は**準備不要**。
- **背景**: 元は Zcash（Electric Coin Co）の Halo2、その後 Ethereum 財団の **PSE** が KZG 版を整備。
- **代表例**: Zcash Orchard、Scroll zkEVM など。強力だが**習得は難しい**。

# B. STARK・再帰・Folding（多端末をまとめる集約向き）

## Plonky2 / Plonky3
- **何者か**: **準備不要で再帰が速い** STARK 系（PLONK＋FRI）。
- **核の仕組み**: Goldilocks という計算に有利な体の上で高速証明。証明の中で証明を検証する再帰が得意。
  Plonky3 はモジュール化した後継。
- **背景**: Polygon Zero が開発。
- **代表例**: Polygon zkEVM、再帰を多用する集約。**BN254 系の署名検証とは体が違い相性に注意**。

## Nova / HyperNova（＋ Sonobe）
- **何者か**: **Folding（畳み込み）**という新しい集約方式。N 個を1個ずつ“足し込む”ように束ねる。
- **核の仕組み**: 各ステップの実行を逐次 fold して1つに凝縮 → 最後に1回だけ SNARK 圧縮。
  **ピークメモリが小さい**のが特徴。
- **背景**: Microsoft Research（Srinath Setty ら）発。実装 **Sonobe** は 0xPARC/PSE 系。
- **代表例**: 長い反復計算(IVC)、**端末側での逐次集約**。本案件の集約代替に相性良し。

## Cairo（＋ Stwo）
- **何者か**: StarkWare の**STARK 言語＋VM**。Starknet の実行環境。
- **核の仕組み**: Cairo で書いた計算を STARK で証明。準備不要。Poseidon がネイティブで速い。
  新プローバ **Stwo**（Circle STARK）は高速化。
- **背景**: StarkWare が開発。モバイル証明の大規模実証（FibRace）でも使われた。
- **代表例**: Starknet 全般、モバイル証明。ただし**検証は Starknet 前提**。

# C. zkVM（回路を書かず“普通のコード”で）

## RISC Zero / SP1
- **何者か**: **普通のプログラム（主に Rust）の実行**そのものを証明する仮想マシン(zkVM)。
- **核の仕組み**: RISC-V の命令実行を STARK で証明。回路設計が要らず、複雑なロジックをそのまま書ける。
- **背景**: RISC Zero（RISC Zero 社）、SP1（Succinct 社）。汎用検証可能計算の潮流。
- **代表例**: 汎用のオフチェーン計算、ロールアップ。**証明生成は重く、当面サーバ/GPU前提**。

---

# D. モバイルへの橋渡し

## Mopro（Mobile Prover）
- **何者か**: 証明系そのものではなく、**既存の証明器をモバイルアプリに載せる“橋渡し”ツールキット**。
- **核の仕組み**: circom(Groth16/rapidsnark)・halo2・Noir などのプローバを、iOS(Swift)/Android(Kotlin)/
  **Flutter**/React Native の**バインディングに自動生成**する。
- **背景**: Ethereum 財団の **PSE（Privacy & Scaling Explorations）** が主導。
- **代表例**: モバイルでのオンデバイス証明アプリ全般。**本案件の端末証明の配布を一本化できる**。

---

# E. これらを支える部品（土台ライブラリ）

- **circomlib**: circom 用の標準回路集（Poseidon・EdDSA・比較 等）。本案件が多用。
- **arkworks**: Rust の ZK 部品群（有限体・曲線・Groth16 等）。Nova/Sonobe や ark-circom の土台。
- **Barretenberg**: Aztec の C++ 証明バックエンド。Noir を動かす本体。WASM 版もある。
- **witnesscalc**: circom の witness 生成を高速化する C++ 実装。モバイルで効く。

## 一言まとめ表

| 名前 | 種別 | 一言 |
|---|---|---|
| circom + snarkjs | 言語＋証明系(Groth16) | ZK回路記述の定番、実績豊富 |
| rapidsnark | 高速プローバ | circom回路を端末で速く証明 |
| gnark | Go 証明系 | 集約・再帰に強いサーバ向け |
| Noir + Barretenberg | 言語＋証明系(Honk) | 書きやすい・準備不要 |
| halo2 | 証明系(PLONK) | 高度だが難しい |
| Plonky2/3 | STARK | 準備不要・再帰高速 |
| Nova / Sonobe | Folding | 省メモリで逐次集約 |
| Cairo / Stwo | STARK言語＋VM | Starknet の土台 |
| RISC Zero / SP1 | zkVM | 普通のコードで書ける（重い） |
| Mopro | モバイル橋渡し | 既存証明器をアプリ化 |

→ 本案件の現状: **circom＋rapidsnark（端末）＋ gnark（集約）**。
モバイル配布は **Mopro**、準備の根治は **Noir**、端末側集約は **Nova** が次の検討先（詳細は 02/03）。

## 2. Noir 版（`noir_experiment/`）— 実測済み（nargo 1.0.0-beta.22）

`week19/noir_experiment/` に、同等の意味を持つ回路を用意し**実際に動かした**:
- RSSI検証＋距離検証＋多端末(N=3)の K-of-N 合意を **1回路**で（Poseidon/EdDSA は次段）
- 計測環境: nargo 1.0.0-beta.22（macOS x86_64）

計測環境: nargo 1.0.0-beta.22 / bb(Barretenberg) 5.0.0-nightly.20260522（UltraHonk）。

測定結果（proof→verify まで通した）:

| コマンド | 結果 |
|---|---|
| `nargo test` | **3/3 通過**（正常 count=2 / 合意未達 fail / ドローン束縛違反 fail） |
| `nargo info` | ACIR **92 opcodes** |
| `nargo execute` | witness 生成成功、**回路出力 = 2**（整合2端末 ＝ 期待通り） |
| `bb gates` | **回路サイズ 2,953 ゲート**（UltraHonk・R1CS制約に近い指標） |
| `bb prove` | **証明生成 0.11s**、proof サイズ **≈14.6 KB** |
| `bb verify` | **「Proof verified successfully」・0.02s** |

導入メモ（つまずき）:
- 最新 nargo v1.0.0-beta.23 は**リリースにバイナリ未添付(assets 0件)**で `tar: Unrecognized archive
  format`。**`noirup -v 1.0.0-beta.22`** で回避（このマシンは Intel/x86_64）。
- bb は `bbup -nv 1.0.0-beta.22` で noir 互換版(5.0.0-nightly)を自動解決。UltraHonk では
  `bb write_vk` → `bb prove -k vk` → `bb verify -k vk -p proof -i public_inputs` の順。

### circom との比較（実測）

| 項目 | circom（Groth16, 実測） | Noir（UltraHonk, 実測） |
|---|---|---|
| RSSI整合ロジックの規模 | R1CS **649制約**（1端末・合意なし） | **2,953 ゲート**（N=3＋合意込み） |
| 署名EdDSA1件（参考） | circomlib 実装済 | 文献値 ≈24,472（Noir版は未実装） |
| 証明生成 | ≈1.4s（snarkjs, フル11.8k回路） | **0.11s**（この小回路） |
| 証明サイズ | 定数・**小**（Groth16 ~200B級） | **≈14.6 KB**（大きめ） |
| ネイティブ検証 | 速い | **0.02s** |
| セットアップ | **回路別セレモニー要** | **不要（universal）** ← 実機で確認 |
| オンチェーン検証 | **≈348k gas** | UltraHonk ≈2.4M gas（文献） |

**読み取り（実測に基づく）**:
- **セットアップ不要が実機で確認できた**（★1 の根治が本当に効く）。
- **証明生成は速い**（小回路で 0.11s）。一方 **証明サイズは Groth16 より大きい（~200B → ~14.6KB）**＝
  オンチェーン検証が高くつく方向（文献の 2.4M gas と整合）。
- 規模比較（649 R1CS vs 2,953 ゲート）は**証明系が違うので厳密には別指標**だが、
  Noir 側は N=3＋合意まで含んでこの規模で、**同じ桁**に収まっている。
- **未実装の Poseidon/EdDSA を足すと本命の重い部分が見える** → 次段で同機能比較を完成させる。

## 3. 読み取り（現時点の結論）

- **現行回路は“小さい”**: 約12k制約は Groth16 では小規模。**証明が回るか自体は問題にならない**
  （デスクトップ1.4s、端末も rapidsnark で実用域、FibRace の一般傾向 <5s）。
- 差が出るのは**制約数そのものより、セットアップ・オンチェーンgas・集約方式**（＝これまでの比較の通り）。
- Noir に替えても**証明生成は速い一方、オンチェーン検証gasが約7倍**になる見込み。数値は導入後に実測で確認。

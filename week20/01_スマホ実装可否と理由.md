# スマホで実装できる？ ── 可否と理由（やさしくまとめ）

作成日: 2026-07-23 / 目的: 各 ZKP フレームワークが「スマホ（オンデバイス証明）で実装できるか」を
○/△/✕ で示し、**なぜそうなるか**を平易に説明する。関連: week20/00・week19。

---

## まず「何が可否を決めるのか」（3つの条件）

スマホで証明を作る＝**証明生成プログラム(prover)を電話の中で動かす**こと。動くかどうかは次の3点で決まる。

1. **チップに合う形にできるか**（arm64 ネイティブに変換できるか）
   - 電話の CPU は arm64。prover をこの形にコンパイルできないと動かない。
2. **軽いか**（メモリ・時間が電話で現実的か）
   - 証明生成は重い計算。RAM を食いすぎたり、何分もかかると実用にならない（目安: 3GB以上のRAM・数秒以内）。
3. **アプリから呼べるか**（Flutter などから叩ける“橋”があるか）
   - 公式プラグイン(Mopro等)があれば楽。無ければ自分で FFI 配線が要る。

→ この3つが揃えば「実装できる(○)」、1つでも欠けると「条件付き(△)」や「不向き(✕)」になる。

|---|---|---|
| **circom/Groth16（rapidsnark）** | **○ できる** | 小さく速い C++ prover が元から arm64。アプリで実証済 |
| **Noir/UltraHonk（bb）** | **○ できる（条件付き）** | arm64 で動くが Android のリンクに Zig が要る |
| halo2 | △ できる（自前配線） | Rust で arm64 化は可。回路作りが難しい |

| RISC Zero / SP1（zkVM） | ✕ 不向き | プログラム全実行を証明＝重すぎ。サーバ/GPU 前提 |

## なぜそうなるか（各フレームワーク・やさしく）

### ○ circom/Groth16（rapidsnark）── 実装できる
- prover が **小さくて速い C++**。電話の arm64 向けが最初から用意されている。
- 証明も**とても軽い**（この案件の小回路で **約0.01秒**、証明サイズ ~200バイト）。
- **このアプリで実際に動作**し、Mopro で **APK まで作れた**（実証済）。
- 唯一の弱点は「回路ごとに鍵作りの儀式(トラステッドセットアップ)が要る」こと。動作可否には影響しない。

### ○（条件付き）Noir/UltraHonk（bb）── 実装できるが Android に一手間
- prover(bb) は arm64 で動き、証明も速め（約0.13秒）。**iOS は素直**。
- **Android だけ落とし穴**: bb が使う C++ 標準ライブラリが特殊で、Android の NDK とそのままでは噛み合わず、
  **Zig というツールを間に挟んでビルドする必要**がある（今回の検証で判明）。
- 準備の儀式が要らない（★1不要）のが利点。証明サイズは大きめ(14.6KB)。

### △ halo2 / Plonky2 / Nova ── 動くが「橋」を自分で作る
- どれも **Rust** 製で、arm64 にコンパイルすること自体はできる（＝条件1はOK）。
- ただし **Flutter からワンタッチで呼べる公式プラグインが無い**（条件3が弱い）。
  → `dart:ffi` で「電話用の部品(.so/.a)を作ってアプリから呼ぶ」配線を**自分で書く**必要がある。
- 用途の違い: halo2＝高度な回路、Plonky2＝準備不要・再帰が速い、Nova＝**省メモリで電話に向く**（多端末集約の将来候補）。

### ○（別土台）Cairo / Stwo ── スマホ証明は得意だが土俵が違う
- モバイルで証明を作る実績が**最も豊富**（多機種で5秒以内の大規模実証あり）。条件1〜3は満たす。
- ただし **証明の“検証”が Starknet というチェーン前提**。本案件は EVM（イーサリアム系）なので、
  決済・検証の土台ごと乗り換えになる＝「動くけど今の設計に合わない」。

### ✕ gnark ── 重くてサーバ向き
- Go 製で、技術的には電話に載せられる(gomobile)が、**証明生成が重く電話では実用的でない**。
- 本案件では **集約(サーバ側)** の担当。端末の証明器には使わない。

### ✕ RISC Zero / SP1（zkVM）── そもそも重すぎる
- 「回路」ではなく **プログラムの実行そのものを丸ごと証明**する仕組み。柔軟だが計算量が桁違いに大きい。
- 今は **サーバや GPU で証明を作る前提**で、電話単体では現実的でない（将来の高性能端末で再評価）。

---

## まとめ（一言で）

- **今すぐ電話で実装できる本命 = circom/Groth16（rapidsnark）**。小さく・速く・すでにアプリで動く。
- **Noir も実装できる**が、**Android は Zig が要る**・証明が大きい・gas 高い、というトレードオフ。
- halo2/Plonky2/Nova は**動くが自分で橋を作る**手間。Cairo は**土台が違う**。gnark と zkVM は**重くて不向き**。

→ 可否を分ける本質は「**arm64 にできるか・軽いか・アプリから呼べるか**」の3点。

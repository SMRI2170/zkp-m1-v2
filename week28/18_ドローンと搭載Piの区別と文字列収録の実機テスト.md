# ドローンと搭載Piの別記録・文字列収録

2026-11-11。ドローンに研究用Pi送信機も搭載する想定に合わせ、送信機ごとの別ID／BSSID、ローカル分類、解析失敗時の生データ保存を追加した。

**別IDのPi送信機2台を同時送信し、各121件を別送信元として受信できた。解析不能データ53件もRSSI・元バイト列付きの文字列で保存。さらに位置なしIDマーカーをBで57件、Cで54件受信した。**
実ドローンの代わりに試験用Piを用いた事前試験であり、M350実機を受信した結果ではない。

## 使える形にしたもの

| 機能 | 動作 |
|---|---|
| `transmit-marker` | 各Pi固有の研究用IDだけを手動送信。位置・GPS情報なし |
| 別のIDとアドレス | `PI-RID-*`と個別LAAを初回生成し、端末内設定に保持 |
| ローカル分類 | ドローン／搭載Pi／不明を申告ID・BSSIDと利用者登録で対応付け |
| JSONL＋TXT | 同じ観測を構造化JSONLと1行文字列の両方に逐次保存 |
| 生データの保持 | デコード不能でもODID Vendor IE全体をHEXで保持 |
| 明確な不明扱い | 正常に読めないID・位置を創作しない。競合する登録は不明 |

送信コードの最大120秒、既存ネットワーク・チャネルを変えない制限、他のhostapdがあれば起動拒否する制限を維持した。以前のcaptureや設定を削除しない。

## 実機試験

### 1. 2送信元の同時受信

Aを「搭載Pi」、Bを「ドローン代替Pi」として、異なる試験用Specific Session ID・異なるlocally administered BSSIDで同時送信した。
Cは2452MHz・0.25秒要求・0.1秒キャッシュ読取り、35秒収録。送信IDとBSSIDの両方でローカルラベルを付けた。

| 送信元 | 受信先 | 送信内容と一致した保存数 | 解析 | 分類根拠 |
|---|---|---:|---|---|
| A：搭載Pi役 | C | 121 | decoded | 利用者登録のID＋BSSID |
| B：ドローン代替Pi役 | C | 121 | decoded | 利用者登録のID＋BSSID |

2種類の申告ID・別BSSIDが別観測として保存され、RSSI欠測なし。TXTはJSONLから生成した各行と完全一致。
同じ申告IDでもBSSIDが違えば別記録になることはPython/KMPの自動テストで確認した。両方のID・BSSIDを同時に偽装した送信機まで識別した試験ではない。

### 2. 解析失敗時の文字列保存

Aから意図的に未対応メッセージ版を送信し、Cで15秒収録した。送信内容・counterが一致した53件はすべてinvalidとして保存された。

- 申告IDは空、不明な位置を補完しない。
- RSSI、BSSID、時刻、Vendor IE全体のHEXは残る。
- BSSIDだけの明示登録により「搭載Pi（ID未解析）」と記録。分類はローカル登録による候補で、認証ではない。
- ファイル全体は55行。前試験の正常キャッシュ2行が混在し、コマンド終了コードは0だった。**終了コードだけで、この53件を正常に解析できたと扱わない。**
- 生HEXと送信receiptの内容ダイジェスト・counterを照合し、対象53件を選択して確認した。

### 3. GPSなし・位置なしのID送信

最終起動コマンド `~/zkp-beacon-observer/transmit-marker --duration 40` をAで実行し、B/Cで各15秒収録。

| 受信先 | 一致した保存数 | 位置メッセージ | 分類 |
|---|---:|---:|---|
| B | 57 | 0 | Piマーカー（申告・未検証） |
| C | 54 | 0 | Piマーカー（申告・未検証） |

両方ともRSSIあり、TXTとJSONLの一致、Basic IDだけであることを確認した。計111件を「位置情報を取得できた」と表現しない。
A/B/Cへ同じ最終release `c77bf72bcec0`を導入し、転送した15ファイルのハッシュ一致、再導入後も各PiのID／BSSIDが変わらないこと、3台の値が相互に異なることを確認した。
Cは現在5GHzに接続しており、Cからこの方式で送信する実機試験は未実行。勝手な接続先・チャネル変更はしない。

## 何を区別できるか

- 搭載Piとドローンの送信に別ID／別BSSIDがあり、観測できれば別記録として残せる。
- 利用者が登録したラベル、または`PI-RID-`申告マーカーによる分類。未知の送信元を自動でドローンと断定しない。
- ID・BSSIDが同じに偽装された場合、この分類だけでは物理送信機を識別できない。`identity_verified=false`を保持する。
- RSSIの強弱でドローン／Piを決めない。両方が同じ機体に載る場合も、各送信機の無線特性は別に扱う。
- 対象ODID IEのデコード不能時はHEXを保存するが、Android/Piの通常スキャンで未知の全通信方式・全パケットを捕捉できるわけではない。

実際のM350から取得した申告ID・BSSIDで登録を行い、同時受信を確認する作業は未実行。PixelもADB／mDNSに見えず、今回APKのインストール・登録UI操作は未実行。
飛行、120秒超の送信、ネットワーク圏外動作、GPS連携、機体認証・DRIP・位置偽装検出は今回の達成範囲に含めない。

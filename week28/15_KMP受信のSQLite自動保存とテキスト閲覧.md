# KMP受信：SQLiteを標準保存先にする

## 変更した動作

**v0.6は「受信開始」だけで、受信した観測をアプリ内SQLiteへ自動保存する。**
JSONLのエクスポートや「記録開始」を押すことを、通常保存の条件にしない。
グラフ描画は外し、データ表示はボタン操作で更新する。受信・保存と画面表示を分離した。

| 操作 | 動作 |
|---|---|
| 受信開始 | Foreground Serviceで受信し、DBへ自動保存 |
| データ表示・更新 | DBの最新50件を文字列表示。受信中でも更新可能 |
| 記録開始／停止 | 任意の追加JSONL・監査ログ。DB自動保存とは独立 |
| 受信停止 | 新しい受信を止め、保存待ちは書込みを続ける |
| DB全件JSONL | 受信停止・保存待ち0件で全件を書き出す |
| 最新50件テキスト | DBに保存済みの最新値をTXTへ書き出す |

「DB件数」は確定した保存数、「保存待ち」はワーカーへ渡した未確定分。
画面を更新しなくても保存を継続する。件数等の小さな表示は5秒間隔で更新するが、データ本文は自動再描画しない。

## 保存形式

Android標準のSQLiteOpenHelperを使用。外部DBサービス・追加DBライブラリ・ZKPは不要。
解析・文字列／JSON生成・重複キーはKMP共通コード、SQLite操作はAndroid実装。iOS/JVMのDB実装を追加したものではない。

保存先：アプリ専用 `files/captures/database/observations.sqlite`。

- 観測時刻、受信推定UTC、RSSI、周波数、申告ID、申告座標・高度。
- source_type、cache_stale、parse_status、重複キー。
- 正規化したJSONと、1観測1行の文字列。
- JSONのrid_messagesには解析済みBasic ID／Locationを含め、既存のpayload hexも保持する。

申告座標は真位置ではない。欠測はNULLを保持し、0へ置換しない。
取得できない物理フレーム識別や受信機の絶対電力校正は、引き続き未確認として扱う。

## 保存と容量の扱い

- 書込みは単一ワーカー、待ちキュー最大256件。
- DB本体64MiB・10万行を上限とし、満杯・書込み失敗・キュー超過では受信を止めてエラーを表示する。
- 既存データを自動削除しない。既にキューへ受け付けた書込みは、停止後も可能な範囲で処理する。
- DB破損時の自動削除・破壊的マイグレーションは実装しない。
- ディレクトリ0700、DBと保持ジャーナル0600。
- 全件書出しはストリームで行い、DB全体をメモリに展開しない。書出し中は受信開始を止め、保存を長く待たせない。

起動期間・送信元・周波数・観測時刻・Vendor内容を使ったキーをDBのUNIQUE制約で管理する。
BOOT_COUNTが不明ならプロセススコープへ退避するため、跨プロセスの完全な重複排除は保証しない。
時刻不明の観測を、別プロセスでも同じものと断定しない。物理パケット同一性を証明する機能ではない。

## Pixel 8で実行した検証

送信元はPi Aの上限付きテストBeacon、申告ID・位置は合成値。M350実機ではない。
標準30秒・スキャン制限ONのまま実行し、開発用設定への変更はしていない。

| 確認 | 結果 |
|---|---|
| 任意JSONLの記録開始を押さずに保存 | DBへ3件保存 |
| 追加ログのセッションポインタ | 試験前後で不変。DB単独で保存したことを確認 |
| SQLite integrity_check | ok |
| 型付き列と正規化JSON | RSSI・申告ID・申告座標の対応を照合 |
| 送信側との照合 | 3件ともcounter 226・Vendor IEダイジェスト一致 |
| APK更新・プロセス再起動 | 3件を保持 |
| 再起動後の文字列表示 | DBから保存値を表示。メモリ履歴に依存しない |
| DB全件JSONLのSAF書出し | 3件、DBのraw_json列と完全一致 |
| DB最新TXTのSAF書出し | 3件、DBのtext_line列と完全一致 |
| DB・ジャーナルの権限 | 0600、親ディレクトリ0700 |
| 終了時 | 保存待ち0、受信・記録停止、Pi送信終了・一時AP削除 |

画面の文字列折返しとスクロール表示を画像で確認した。生DB・JSONL・TXT・画面・レシートはignored capturesへ保存し、公開しない。
[匿名検証結果・APKハッシュ](results/kmp-local-database-20261110-a/validation.json)とビルド／チェックログを保存した。

Android/JVM共通テスト各24件、Python12件、APK・JVM配布物・Lintが成功。既存UAV77件・contracts48件・Goも成功。
共通テストには、JSONの解析済み項目・文字列の改行エスケープ・表示行数上限・起動期間を跨ぐ重複キーの検査を追加した。
SQLiteの実機確認とホストテストは別物として扱う。

## 使い方と残件

1. 「受信開始」。DB件数・保存待ちを確認する。通常保存に「記録開始」は不要。
2. 必要なときだけ「データ表示・更新」で保存値を表示する。
3. 受信停止後、保存待ち0件で「書き出し」→「DB全件JSONL」を選ぶ。

以前のJSONLは保持し、DBへ自動取り込みはしない。以前の「受信全体CSV」はメモリ履歴、セッションCSVは任意記録の対象であり、DB全件のCSVではない。
アプリ再起動ではDBが残るが、アンインストール・アプリのデータ消去では消える。
強制終了の瞬間に保存待ちだった分まで保持できる保証はない。詳細なPSS・要求成否等の監査には任意JSONL記録も使う。

M350実機、長時間／DozeでのSQLite収録、満杯、破損、移行、キュー超過、書込み途中の強制終了は未実行。
画面の簡素化による受信速度向上も新たに計測していない。旧1.51秒の結果を新版の速度として扱わない。
研究用のRID観測PoCであり、機体・位置・センサー・観測ハードウェアの真正性やDRIPを検証するものではない。

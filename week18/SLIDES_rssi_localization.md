## S2. 背景 — RemoteID の「位置」は信用できるか

- ■ RemoteID = ドローンが ID・位置・速度を自己申告で放送する仕組み
- ■ 受信側は放送を鵜呑みにするしかない構造的弱点
  - ・ 位置の書換だけで成立する偽装
- ■ 目標 = ドローン無改造での放送位置の真偽判定
- ■ 受信側で使える物理量 = RSSI（受信電波強度）と自端末の GPS

> ノート: 対象は「位置詐称」。中継(ワームホール)は RSSI 単独では原理的に防げない点は S14 で明示。

---

## S3. 核アイデア — 2つの独立な距離の突き合わせ

- ■ 同じ放送に対する 2 通りの距離
  - ・ `d_claim` = ‖放送位置 − 自端末GPS‖ … 幾何由来
  - ・ `d_meas` = RSSI からの推定距離 … 物理由来
- ■ 本物なら一致、位置詐称なら乖離
- ■ 放送単独では不可視、物理実測との重ね合わせで初めて見える矛盾

```
放送位置 P_claim ──(幾何)──▶ d_claim
                               ⇕ 一致？
受信 RSSI ───────(物理)──▶ d_meas
```

> ノート: これは 1 端末ぶんの判定。複数端末による位置「特定」は S9 で拡張。

---

## S4. 前提① — RSSI は距離の「対数」で決まる

- ■ 距離とともに対数的に減衰する電波

```
RSSI(d) = A − 10·n·log10(d)
d_meas  = 10^((A − RSSI) / (10·n))     ← 逆に解けば距離が出る
```

- ■ 2 つのパラメータ = `A`（1m時RSSI）と `n`（伝搬指数 2.0〜4）
- ■ このRSSIならこの距離（A=−40, n=2.5 の目安）

| 受信 RSSI | 推定距離 |
|---|---|
| −65 dBm | 約 10 m |
| −77 dBm | 約 30 m |
| −90 dBm | 約 100 m |

> ノート: A・n は実機 DJI で（距離,RSSI）を数十点とり最小二乗フィットで決める（S13/後述の較正）。

---

## S5. 前提② — 1台の RSSI は本質的に粗い（±4dB → 距離は×2幅）

- ■ 反射・フェージングによる ±4dB 程度の RSSI ノイズ
- ■ dB 誤差の距離への掛け算的な効き方

```
距離の倍率 = 10^(k·σ / 10n)
k=2（約95%）→ 10^(2·4/25) ≈ 2.1 倍
```

- ■ 「測った距離」に対する実際の幅

| 端末が測る距離 | 実際は（±2σ） |
|---|---|
| 10 m | 約 5〜21 m |
| 30 m | 約 14〜63 m |

- ■ 「30mと測っても本当は15〜60m」= 設計全体を規定する前提

> ノート: この幅の大きさが、以降の「比で判定」「複数端末」の理由に直結する。

---

## S6. 考え方A — 掛け算的な誤差ゆえ、判定は「比（％）」で

- ■ 固定幅（±3m など）の破綻（近距離で緩く遠距離で厳しい）
- ■ ずれを比で見る整合スコア

```
ずれ = | log10(d_claim / d_meas) |
整合 ⇔ ずれ ≤ τ,   τ = k·σ/(10n)   (k=2 で ~2σ)
```

- ■ 回路の許容幅 ±90% = この 2σ 倍率（≈2.1倍）由来の値（恣意的な閾値ではない）

> ノート: 回路では log を避け、相対帯の二乗比較に落とす（S17）。

---

## S7. 前提③ — 単発は反射で外れる → 中央値で集約

- ■ マルチパスによる単発 RSSI の飛び
- ■ 同一 UAS_ID の RSSI を M サンプルの中央値へ集約
  - ・ 外れ値へのロバスト性と実効 σ の縮小（平均より脆くない）
- ■ 集約後の値を用いる `d_meas`（M = 5〜10 を推奨）

---

## S8. 考え方B — 細かい詐称は「ノイズ以下」→ 複数端末が必然

- ■ 30m 地点で放送位置を 5m ずらしたときの信号

```
ΔRSSI = 10·n·log10(30/25) = 25·log10(1.2) ≈ 2 dB
```

- ■ 嘘の信号(2dB) < 雑音(4dB) → 1台では埋もれて見えない
  - ・ 1台で捕まるのは「5m先と放送・実は30m」級の粗い嘘だけ
- ■ 複数端末の平均による雑音の √N 縮小

| 端末数 N | 実効ノイズ σ/√N | 2dBの嘘 |
|---|---|---|
| 1 台 | 4.0 dB | ✕ 埋もれる |
| 5 台 | 1.8 dB | ○ 浮かぶ |
| 12 台 | 1.2 dB | ◎ 明確 |

- ■ 「細かい位置詐称の検知に複数端末」= 信号対雑音の必然

> ノート: 評価で N を増やすほど TPR が上がるのは、この √N 効果そのもの。

---

## S9. 複数端末での「位置」特定（多辺測量 / multilateration）

- ■ 単端末の限界 = 距離のみ（発信源は円周上のどこか）
- ■ 空間分散した N 端末の距離の連立による水平位置 (x,y) の特定

```
各端末 W_i=(x_i,y_i,0)、推定距離 d_i、発信源 P=(x,y,h)
d_i² = (x−x_i)² + (y−y_i)² + h²
```

- ■ 基準式 (i=0) との差による h² の消去 → (x,y) について線形

```
d_i² − d_0² = (x_i²+y_i² − x_0²−y_0²) − 2·[x(x_i−x_0) + y(y_i−y_0)]
```

- ■ i=1..N−1 を並べた 2×2 最小二乗での求解（`multilaterate2d`）

> ノート: 3台の具体例（W0=(40,0),W1=(0,40),W2=(−40,0)・各距離40m）で解が(0,0)に定まる。板書向き。

---

## S10. 位置特定 → 詐称判定

- ■ 推定発信源 `P_hat` と放送位置 `P_claim` の水平残差

```
residual = ‖ P_hat(x,y) − P_claim(x,y) ‖
residual > 閾値  ⇒  位置詐称
```

- ■ 空間分散した端末による同時充足の困難さ
  - ・ 真の発信源近くの端末による必然的な矛盾の露呈
  - ・ 単一偽装源では全端末の幾何を満たせない構造

> ノート図: 正常系＝各端末の円が P_claim で交わる / 詐称＝P_hat と P_claim が乖離。

## S11. 【やったこと ②】評価ハーネスの構築

- ■ 実機前に「位置詐称の RSSI 検知力」を数値化する基盤の実装
  - ・ `eval_spoof_detection.py`（依存なし・標準ライブラリのみで再現可能）
- ■ 実装した中身
  - ・ 合成シナリオ = 真の発信源周りへの N 端末分散、`RSSI = pathloss(真距離) + N(0,σ)`
  - ・ Mann-Whitney U による ROC/AUC の厳密計算、FPR 指定でのしきい値と TPR
  - ・ 掃引 = Δ（位置ずらし）/ N（端末数）/ σ（ノイズ）/ 較正ズレ
- ■ 設計値 τ（相対幅）と K（必要台数）の根拠に基づく決定

---

## S12. 評価結果 ① — 融合方式の比較（中央値合意 vs 多辺測量）

- ■ N=6, FPR=5% での比較

| 条件（Δ=20m） | 中央値合意 TPR | 多辺測量 TPR |
|---|---|---|
| σ=4dB（現実的） | 83% | 58% |
| σ=2dB（低ノイズ） | 99% | 99% |
| N=12, σ=4dB | 94% | 93% |

- ■ 結論 = 現実ノイズ＋少数端末での中央値合意（多数決）の優位
- ■ 多辺測量が効く条件 = 低ノイズ or 多端末（N≥12）
- ■ 既定は中央値合意、位置特定は好条件での上乗せ（負の結果＝設計判断の裏付け）

> ノート: 悪条件で最小二乗解が暴れ、正常系残差が広がって閾値が甘くなるのが劣後の理由。

---

## S13. 評価結果 ② — 検知性能の決定要因

- ■ Δ 掃引（N=5）= 位置ずらしと検知率、検知下限 Δ_min
- ■ N 掃引（Δ=30m）= 端末数と TPR、必要台数 K の根拠（＝S8 の √N）
- ■ σ 掃引 = RSSI ノイズの支配性（σ=2→8dB で AUC 大幅低下）
- ■ 較正ズレの頑健性（＝実機較正が必須である根拠）

| 較正 | 検知率 TPR |
|---|---|
| 一致 | 91% |
| n が −0.5 ズレ | 7.7% |
| A が +6dB ズレ | 8% |

> ノート: 要求精度は A を数 dB 以内、n を ±0.5 未満。ズレると検知が崩壊する。

## S14. 脅威モデルと限界（正直に）

| 攻撃 | RSSI での検知 |
|---|---|
| 位置詐称（放送位置だけ書換） | ○ 発信源近くの端末が矛盾 |
| 捏造（存在しない機体） | △〜○ 放送に見合う RSSI が伴わない |
| 送信電力の操作（A を上げて近く見せる） | △ 単端末は騙せるが全端末同時充足は困難 |
| 中継 / ワームホール | ✕ RSSI は中継点を反映（限界） |
| ジャミング / DoS | 対象外（可用性の問題） |

- ■ 主眼 = 位置詐称、限界としての中継の明示（将来 TDoA / 実測裏取りで補完）
- ■ 端末 GPS の信頼 = 端末アテステーション(M3)による別途担保

## S17. 【やったこと ④a】ゼロ知識回路への落とし込み

- ■ `remoteid_consistency_rel.circom`（相対許容版）の実装

- ■ 相対幅 TOL = ±90%、回路規模 ~650 制約

> ノート: 座標は private のまま。位置プライバシーを保った検証。

## S18. 【やったこと ④b】witness 統合と多端末合意

- ■ `remoteid_consistency_rel` の `uav_witness_attestation.circom` への統合
  - ・ `consistency_ok` の public 化と同一 `drone_id_commitment` への束縛
  - ・ `time_bucket` による「同じ放送・同じ時間窓」の端末の束ね
- ■ `AttestationRegistry` での `(drone_id, time_bucket)` ごとの集計

```
consistent ≥ K → trusted     （放送を信頼）
suspicious ≥ K → spoofAlert   （なりすまし警報）
```

- ■ 全体パイプライン

```
受信 ─▶ ログ ─▶ 較正(A/n/σ) ─▶ 中央値集約 ─▶ d_meas ─▶ 整合判定
   ─▶ 回路 → proof → レジストリで束ね & K 合意 → trusted / spoofAlert
```

## S19. 総括 — 前提から設計への筋道

| 前提（RSSIの性質） | 具体的な大きさ | 設計 |
|---|---|---|
| 距離の対数で減衰 | −77dBm≈30m | path-loss で `d_meas` 逆算 |
| ±4dB のノイズ | 30m→15〜60m | 比(log)・相対±90%で判定 |
| 5mの嘘≈2dB<ノイズ | 1台では埋もれる | 多端末（K台合意） |
| 3台で連立可 | h²が消え線形 | 多辺測量は好条件の補助 |
| A,n が環境依存 | ズレると91→8% | 実機較正を前提条件化 |
| 単発は外れる | 反射で数dB飛ぶ | 中央値集約 |

- ■ 各設計が「好み」でなく**RSSI の物理から導かれた必然**
